## 0. 一句话定位

**把 HSH-64 的 64 位结构化语义码，从「只读检索键」升级为「可读写、可遗忘、被反向传播直接编辑的 per-token 参数」，并让它同时充当三件事：token 的语义坐标、共享专家的路由键、二值联想记忆后端的查询键。**

基座大模型冻结不动，我们只训练码本与投影头。于是「参数热更改」退化为**对打包位数组的原子位翻转**，「持续学习」退化为**对码本行的增量编辑**，「自学习」退化为**写入 8 字节 + 重建一个 MIH 桶**。

## 2. 参考实现（HSH-64）的精确约定

我们必须与 `F:\HSH_64` 的二进制格式**逐字节兼容**，否则 Rust 后端无法直接复用。以下均为读源码得到的**事实**，非推测。

### 2.1 位布局（`src/hsh64.rs`）

```
[63:60] feat (4 bit)  ｜ [59:8] sim (52 bit) ｜ [7:0] abs (8 bit)
```

```rust
FEAT_SHIFT = 60;  SIM_SHIFT = 8;  ABS_BITS = 8
raw = (feat << 60) | ((sim & ((1<<52)-1)) << 8) | abs
```

距离：`(a ^ b).count_ones()` —— 单条 `popcnt`。

### 2.2 Deep Hash MLP 结构（`src/deep_hash.rs`）

```
x → [Linear → BatchNorm(eval, eps=1e-5) → ReLU] × depth → Linear → u ∈ R^52
sim = bits of (u >= 0.0)          // 注意：>= 0 置 1
```

### 2.3 模型文件二进制格式（`DeepHashProjection::from_bytes`）

**全部 big-endian。** 魔数 `0xCAB1_DE3D`。

| 偏移 | 字段 | 类型 |
|---|---|---|
| 0 | magic = `0xCAB1DE3D` | u32 BE |
| 4 | version (1 或 2) | u32 BE |
| 8 | dim | u32 BE |
| 12 | hidden_dim | u32 BE |
| 16 | depth (仅 v2) | u32 BE |
| 16 或 20 | n_bits | u32 BE |
| … | mean | dim × f32 BE |
| … | 每层：W(hidden×input)、b、bn_γ、bn_β、bn_μ、bn_σ² | f32 BE |
| … | W_out(n_bits×hidden)、b_out | f32 BE |

> **v1** = 单隐层（`depth=1`, header 20B）；**v2** = 多层（header 24B）。我们的实现**必须同时支持 v1 与 v2 的读取**，导出时用 v2。

### 2.4 自适应 MIH（`src/mih_index.rs` + 论文 Algorithm 2）

```
r ← 0; Cprev ← ∅
loop:
    枚举每段在 Hamming 半径 ⌊r/B⌋ 内的所有段码 → 合并候选 C
    Cnew ← C \ Cprev
    if |C| ≥ max(K, αK) and |Cnew|/|C| < δ: break
    Cprev ← C; r ← r+1
```

### 2.5 贪心比特翻转后处理（论文 Algorithm 1 + 定理 1）

权重矩阵：

```
W_ij = +w_pos  若 j ∈ P_i⁺ (教师 top-P 邻居)
       −w_neg  若 j ∈ P_i⁻ (当前 Hamming top-K 中的非邻居)
        0      其他
```

**定理 1（我们直接复用）**：翻转第 i 项第 b 位的目标变化量为

```
Δ_{i,b} = Σ_{j≠i} W_ij · (1 − 2·1[C_{i,b} == C_{j,b}])
```

选 `argmin Δ`，若 `< 0` 则翻转，否则终止（1-optimal）。

> **这是本项目的关键复用点**：论文用它优化检索码，我们用**同一个算法**优化「码本位的编辑方向」，见 §5.3。

## 4. 核心机制：可写码本（本项目的创新主体）

### 4.1 三层参数

| 层 | 形状 | 精度 | 大小(V=152k) | 更新频率 | 作用 |
|---|---|---|---|---|---|
| `CodeTable` | V × 64 bit | u64 | **1.22 MB** | 慢（滞回翻转） | token 的语义坐标 / 路由键 / 记忆键 |
| `Shadow` | V × 64 | fp16 | **19.5 MB** | 快（每步梯度） | STE 的连续载体，累积后才翻码位 |
| `Projection` | 512→H→52 | fp32 | 585 KB (H=256) | 每步梯度 | 隐状态 → 查询端 sim 码 |

> **为什么必须有三层**：见 §10 风险 R1。`CodeTable` 是"承诺"，`Shadow` 是"犹豫"，`Projection` 是"泛化"。

### 4.2 影子参数 + 滞回翻转（本方案的技术核心）

```
前向：  code[t] = sign(θ[t])          // θ 为 Shadow 行，code 为 u64 位
                 ↑ STE: ∂code/∂θ ≈ I（|θ| ≤ clip 内）
反向：  θ[t] ← θ[t] − η·∇_θ L
翻转：  当 |θ[t,b]| > τ_flip 且 sign(θ[t,b]) ≠ code[t,b] 时，才翻转该位
        τ_flip 初始 = 1.0，随训练线性退火至 0.3
```

**它同时解决两个致命问题：**

| 问题 | 纯位级 STE 的后果 | 加影子参数后 |
|---|---|---|
| **低频 token 学不到** | batch 只覆盖 ~3 万 token，词表 15 万 → 低频词永不更新 | 梯度累积在 fp16 θ 上，跨 step 保留；且 θ 可预初始化，冷启动即可用 |
| **错位无法纠正** | STE 梯度只沿当前码的 ±1 方向，码已错则推它更错 | θ 需先"掉头"跨过 0 才能翻位 → 天然的滞回与确认机制，可纠错 |

**额外收益**：`|θ[t,b]|` 就是该位的**置信度**，可直接用于论文 §5.3 的非对称距离评分，无需额外计算。

### 4.3 码如何注入前向（语义增量）

码必须变成 `d_model` 维向量才能加到 embedding 上。设 `d = d_model`。

**A. 一阶主路径（必做）**

```
u    = sign(θ[t]) ∈ {−1,+1}^64       // 取自 CodeTable/Shadow
z    = V · σ(W_c · u)                // V ∈ R^{d×K}, W_c ∈ R^{K×64}, z ∈ R^d
h_t  = Embed[t] + α·z
```

`K = 512`、`d = 896`（Qwen2.5-0.5B）时约 **0.9 M** 参数，可忽略。

**在线成本核算**（必须计入，否则会低估）：每个 token 需 `K×64 + d×K = 491,520 MACs`。
152k token 的全词表预计算约 **75 GFLOP** —— 单次可接受。
**关键优化（强制）**：`W = V @ σ(W_c · ·)` 可预先合并为 `W ∈ R^{d×64}`（**57k 参数**），
于是在线退化为 `z = W @ u`，即 **每 token 仅 64×d ≈ 57k MACs**。这是唯一的在线形态。

**B. XOR 位组合的二阶项（可选，§4.4）**

**C. 零参数哈希回退方案（对照基线）** —— 见 `【待定 D2】`

> **`α` 的初始化**极为关键：`α` 初始必须为 **0**（而非接近 0 的小数）并作为**可学习标量**。
> `α = 0` 时该路径是严格的恒等映射，基座输出逐位不变 —— 这是「不破坏冻结基座」的**可证明保证**，
> 比"接近 0"强得多。随后由梯度自然打开。

### 4.4 「码作为路由键组合共享专家」的精确实现

我在提问里说"XOR 位组合基矩阵"，但在设计时发现**直接 XOR 矩阵在计算上不可行**（`d²` 展开会使开销超过原模型）。因此给出两档实现，**请你在 `【待定 D1】` 中选定**：

**档位 1（推荐，稳定）—— 低秩 + 二阶交互：**

```
令 u = sign(θ[t]) ∈ {−1,+1}^64
一阶：  z1 = V @ (W_c @ u)                        // 主项
二阶：  z2 = Σ_{(b1,b2) ∈ M} (u_{b1}·u_{b2}) · V2[:, idx(b1,b2)]
        M = { (b1,b2) : CodeTable[t] 的这两个位均为 1 }   ← 这就是"位组合"
输出：  z = z1 + β·z2 ,  h_t = Embed[t] + α·z
```

- `V ∈ R^{d×K}`、`W_c ∈ R^{K×64}`、`V2 ∈ R^{d×K2}`，`K2 = 256`。
- 位组合 (b1,b2) 用固定的无冲突哈希映射到 `[0,K2)`，**无需学习路由**。
- 参数：`d·K + K·64 + d·K2 ≈ 0.9M`。
- **与论文的血缘**：`CodeTable[t]` 的位模式决定激活哪些交互项，这与论文里 `sim` 码决定落入哪个 MIH 桶在结构上同构。

**档位 2（激进）—— 真正的 XOR 权重矩阵：**

```
W_t = W_base ⊕ (u 广播出的掩码)   // 逐元素 XOR 打包位
```
只在「把二值化扩展到底座权重」时才可行（§8 二期）。**一期不做。**

### 4.5 码的位段权限（把稳定性/可塑性困境降维成"哪几位可写"）

| 字段 | 位 | 权限 | 理由 |
|---|---|---|---|
| `feat` | 63:60 | **冻结**（预训练后锁死） | 粗粒度类别，语义分区的骨架，动了会全局重排 |
| `sim` | 59:8 | **可写**（主学习区） | 语义主体，梯度主要作用于此 |
| `abs` | 7:0 | **半冻结** → `【待定 D3】` | 论文定义为"簇内完美哈希/平局决胜"；若它参与反传学习会失去平局决胜的确定性 |

## 5. 训练路线

### 5.1 阶段 0：语义坐标锚点（**第一个里程碑，风险最低，必须先做**）

**目的**：让码本在「一张白纸」上有正确的初始语义几何。若跳过此步，码是随机的，反传只能学到噪声。

1. 用 `F:\hsh64_models\bge-large-zh-v1.5` 对 `vocab_3109.txt` 生成 1024 维语义嵌入 `T`。
2. 训练 Deep Hash 投影头（512→H→52）**完全按论文 §5.2.2**：`L_info + λ_q·L_quant + λ_b·L_balance`，STE，Adam，lr=1e-3。
3. 评测纯 Hamming Recall@10。
4. **用论文 Algorithm 1 贪心后处理**提升码质量。

**验收标准**：在 3109 词上复现 **Recall@10 ≥ 0.70**（论文：h256 达 0.7382，h512 达 0.7404）。
**交付**：`codebook_3109.bin`、`proj.hsh`、`sim_override.bin`、Rust 端 `benchmark` 输出 JSON。

> 这一步**不涉及 LLM、不涉及新架构**，纯粹复现论文，是为了先证明「我们真的能造出好的 64 位码」。任何新架构如果没有这个地基，后续全部实验都无法解释。

### 5.2 阶段 1：码本 ↔ LLM 对齐（新架构的核心实验）

1. 加载 Qwen2.5-0.5B（冻结），取隐状态 `h`（**取哪一层：`【待定 D4】`**）。
2. 训练「`h` → 64 位码」的投影头，用阶段 0 的码作为**目标**。

> **实现修正（原稿此处有误）**：不能用 `d_H(sign(proj(h)), CodeTable[t])` 当损失。
> 原因有二：① Hamming 距离对 logits 的分段常值，梯度几乎处处为 0；
> ② 若用 `softplus(−y·u)` 展开成 64 项，则需对 **V=152k 的码表**做全量 64 维 matmul，
> 内存与算力都不可接受（152k×64 中间张量 + 每步 75 GFLOP）。

**正确做法 —— 对 ±1 目标做 smooth-L1（Huber）回归**，它在饱和区梯度有界，且实现极廉价：

```
target = 2·CodeTable[t] − 1  ∈ {−1,+1}^64       # 预先展开缓存，152k×64 × fp16 = 19.5 MB
L_align = Σ_t  smooth_L1( proj(h_t), target[t] )
        + λ_ce · CE( LM_head(h), next_token )    # 防止隐状态被拉坏
```

- 只对 batch 内的 token 计算 → 每步开销 `B×52`，可忽略。
- `sign(proj)` 与 CodeTable 的一致性由**周期性全量评估**（而非每步损失）监控。
- 加少量 bit-balance 正则防止 52 维输出全塌到同一侧。

3. 加入语义增量路径（§4.3），`α` 从 0 warmup。

**验收标准（已按论文 Prop.2 校准）**：随机 52 位码的期望 Hamming 距离为 `M/2 = 26`，`σ = √(M/4) = 3.61`。
因此：
- **未对齐基线**应落在 `26 ± 3.6`；
- **合格线**：未见 token 的码与阶段 0 锚点码平均 Hamming **< 16 bit**（即比随机好 ~3σ）；
- **目标线**：**< 13 bit**（论文优化后正样本对均值 ≈ 8 bit，此处因跨模态对齐放宽）。

### 5.3 阶段 2：码本位编辑 + 遗忘 + 自学习闭环

**训练时**：`θ` 走梯度（§4.2），每 `N` 步执行一次滞回翻转。

**离线编辑（复用论文 Algorithm 1）**：把目标函数从"检索召回"换成"语言建模损失"，用 `Δ_{i,b}` 的**有限差分**版本：

```
Δ_{t,b} = L(code 翻转第 t 个 token 的第 b 位) − L(code)
```
对每个 batch 只对 batch 内出现的 token 计算（等价于论文里只对相关 pair 计算 `Δ`）。
> **注意**：论文的 `Δ_{i,b}` 有闭式解（因为目标是 Hamming 距离的线性函数）。LM 损失没有闭式解，所以这里退化为**有限差分**，成本为 `batch_tokens × 64` 次前向。当 batch 内唯一 token 数 = U 时，一次扫描成本 ≈ `U×64` 次前向 —— **这个开销必须用批处理摊销**（把所有候选翻转堆成一个 batch 并行前向）。见 §10 风险 R4。

**遗忘系数**：

```
每步：  θ[t] ← θ[t] · λ_t^Δt              # Δt = 距上次触碰的步数
        λ_t = λ_base ^ (1 + ν·freq[t]^-1)  # 低频 token 的 λ 更小 → 忘得更快
        【待定 D5】：λ_base 初始值与 freq 的定义
翻转门槛：|θ[t,b]| 因衰减跌破 τ_freeze → 该位永久冻结（"长期记忆固化"）
```

**自学习闭环（单跳知识问答）**：
```
① 写入：把陈述句 "X 的 Y 是 Z" 编码 → 64 位键 k → 后端存 (k, v)
② 查询：只给 "X 的 Y 是?" → 模型生成查询码 → popcount 检索 → 返回 v
③ 指标：命中率（Hit@1 / Hit@10）
```
**验收标准**：写入 500 条合成知识，Hit@10 ≥ 0.60，且**基座 PPL 退化 < 2%**。

## 6. 二值联想记忆后端

### 6.1 存储格式（每条目 16 字节）

| 字段 | 宽度 | 说明 |
|---|---|---|
| `key` | u64 | HSH-64 码（**与参考实现逐位兼容**，§2.1） |
| `value` | u64 | 二值码值（学习到的联想内容，`【待定 D6】`决定其语义） |

V = 152k 时全量码本 **2.4 MB**。

### 6.2 查询

```
命中 = argmin_j popcnt(key_q XOR key_j)      // 暴力：O(N)
```

### 6.3 写入（热更改，本项目的落地价值）

无梯度、无重训、无锁：

```
1. 计算新条目 (k, v)
2. 写入 entries[N]（原子追加）
3. 对 k 的 B 个段，向对应倒排桶追加 id
4. epoch 递增，读者用 RCU/ArcSwap 拿到新快照
```

**延迟**：O(1) 位运算 + 一次原子指针交换。**旧的基座权重一个 bit 都不动** → 换域遗忘严格为 0。

### 6.4 为什么一期不用 MIH（含定量论证）

论文 MIH 的期望候选数（定理 4）：

```
E[|C|] ≤ N · (1 − (1 − V(M/B, ⌊r/B⌋)/2^{M/B})^B)
```

在 **N = 150k、M/B = 8 bit/段** 时：

| 半径 r | 每段半径 | V(8,·)/256 | E[候选池] |
|---|---|---|---|
| 0 | 0 | 0.0039 | 11 340 |
| 1 | 0 | 0.0039 | 11 340 |
| 2–7 | 0 | 0.0039 | 11 340 |
| 8 | 1 | 0.0352 | ~84 000 |

**结论**：要么候选池 1.1 万（→ 退化为 O(N)），要么突然爆炸到 8.4 万（**超过暴力扫描**）。MIH 的索引开销（13×256×150k bit ≈ **62 MB**）反而使内存膨胀 26 倍。

> **一期决策**：**暴力 popcount**。`150k × 8 字节 = 1.2 MB` 码本完全塞进 L2/L3 缓存；SIMD 一次处理 4–8 个 u64，实测预期 **< 1 ms**。
> **二期**：当 N > 10⁶ 时再引入 MIH，且需重新设计分段数 `B`（`【待定 D6-b】`）。Rust 端**保留 MIH 模块**（直接复用 `F:\HSH_64\src\mih_index.rs`），用 feature flag 切换。

### 7.2 热替换的原子性设计（这是"无损"的技术保证）

```rust
// 读者路径：无锁、无等待
let snap: Arc<Snapshot> = self.snapshot.load(Ordering::Acquire);   // arc_swap
let codes = &snap.codes;        // &[u64] —— 不可变切片，读者永不阻塞

// 写者路径：copy-on-write
let mut new_codes = snap.codes.clone();     // 只 clone 受影响的桶
new_codes[t] ^= bit_mask;                    // 位翻转
let mut new_snap = Snapshot::from(snap);
new_snap.codes = Arc::new(new_codes);
new_snap.version = snap.version + 1;
self.snapshot.store(Arc::new(new_snap));     // 一次原子指针交换
```

**保证**：
- **读者不阻塞、不收锁**（`arc_swap` 的 acquire 是无锁的）
- **单次翻转对所有并发读者原子可见**（要么全看到旧版，要么全看到新版，绝无中间态）
- **回滚 = 存回旧 `Arc`**，O(1)

### 7.3 位级翻转的并发安全边界

> **注意**：`new_codes[t] ^= mask` 是**对 clone 出来的私有副本**操作，因此不需要 CAS 循环。这与直接原地改 `&[u64]` 有本质区别 —— 后者是 UB。**这一点必须在代码审查中重点确认。**

## 15. 对 HSH-64 论文数学命题的核查（2026-02-12 补录）

为解决「我们的新架构是否真的需要可写码本」这个问题，我（在本机、纯 CPU、零模型依赖）

### 15.1 核查结果

| 命题 | 内容 | 结果 |
|---|---|---|
| Prop.1 | Hamming 球容量 `V(52,10) ≈ 2.5e10` | ✅ 一致（实为 2.04e10，属四舍五入表述） |
| Prop.2 | `E[d_H] = M/2`，`Var = M/4` | ✅ 一致（26 与 3.6056）—— **全篇最重要的基线常数** |
| **Prop.3** | **称 `d ≤ 18` 时 `N·V(52,d−1) < 2^52`** | ❌ **错误，实际最大 `d = 14`** |
| Prop.4 | 非对称距离分解 | 未复核（叙述性，不影响架构） |
| Thm.1 | 比特翻转的梯度闭式解 `Δ_{i,b}` | ✅ 代数正确，我们直接复用（§2.5） |
| Thm.4 | MIH 期望候选数 | 已用于 §6.4 的定量论证 |

### 15.2 Prop.3 错误的精确定位

论文原文（第 11 页）：

> 对 d = 18，`V(52,17) ≈ 1.3×10^12`，`N·V(52,17) ≈ 3.9×10^15 < 2^52 ≈ 4.5×10^15`，故理论上存在这样的码本。

实测：

```
V(52,17)        = 3.9481e+13        （论文称 1.3e12）
V(64,17)        = 2.0926e+15
3109 * V(52,17) = 1.2275e+17   vs   2^52 = 4.5036e+15   → 不成立（超出 27 倍）
3109 * V(64,17) = 6.5060e+18   vs   2^64 = 1.8447e+19   → 成立
```

**根因**：`1.3e12` 与 `3.9e15` 这组数字的量级对应 **M=64** 的 Hamming 球，而非 M=52。
即 `V(M, d−1)` 那一步误用了 64 位空间。旁证：论文 §4「信息论预览」用的 `2^52 ≈ 4.5e15`
是自洽的，只有 Prop.3 的球体积跳到了 64 位。

**逐项重算 M=52、N=3109 下的 Gilbert–Varshamov 界：**

```
d=13:  V(52,12) = 2.8719e+11   N*V = 8.9288e+14   <  2^52   OK
d=14:  V(52,13) = 9.2221e+11   N*V = 2.8671e+15   <  2^52   OK   ← 真正的上界
d=15:  V(52,14) = 2.6912e+12   N*V = 8.3669e+15   >= 2^52   不成立
```

**正确结论：`d ≤ 14`，而非 `d ≤ 18`。**

### 15.3 影响评估（三条，均不要求重跑实验）

1. **不影响任何实验结论。** Prop.3 是纯存在性理论论证，论文的 Recall 数字全部来自真实实验。
   订正它不需要重跑任何训练。

2. **订正后 52 位的选择反而更有说服力。** `(M,d) = (52,14)` 给出 `d/M = 0.269`，
   紧贴 Hamming 界上界（≈0.288）与 Varshamov–Gilbert 界下界（≈0.213）之间 ——
   52 位在信息论上近乎最优，这比一个过强的声明是**更强**的论证。

3. **修正后的界直接强化了本项目的设计动机。** 52 位码在 N=3109 时仅能支持最小距离 14；
   而 Cabinet-BNN 要把词表扩到 Qwen 的 **151,936 token（约 49 倍）**，碰撞压力急剧上升。
   这正是「码必须可写、可增量编辑、可按 token 消亡」的**硬性理由**，而非工程偏好。

| ①「改参数产生链接」 | `W_t = Σ_j s_j(c_t)·B_j`，改码即改该 token 的权重矩阵 | ⚠️ **半实现**：链接是**通过共享基间接发生**的，不是显式的两两关系 |
| ②「新 token 直接添加」 | `CodeTable` 行数固定为 `n_words`，加 token 需重建模型 | ❌ **未实现** |

### 16.3 gap 的机制原因是「交互粒度太粗」

当前实现中，**一个 token 只有一个 64 位码**。改这个码 = 整体换一套权重矩阵。
因此作者想要的「微调它和某几个 token 的关系」**没有对应的自由度** —— 模型只能整体改。

**这解释了 `code_param` 实验为什么失败**（本域均值 0.2862，劣于 shared_ft 的 0.2875，
后向迁移 −0.0536）：离散空间里的大步长更新直接导致优化崩掉。

### 16.4 作者提出的核心问题（本节最重要的内容）

作者判断：

> 「改变参数确实会牵一发动全身，但是**一定存在一个极其优雅的方式解决它**，
> 但是也许目前的前沿科学也是卡在这里。」

**这个判断是准确的，而且指出了本项目的真正研究方向。** 分析如下：

「牵一发动全身」即**稳定性–可塑性困境**。已有解法均不优雅：

| 方案 | 不优雅之处 |
|---|---|
| EWC / SI / MAS | 需 Fisher 信息，O(参数量) 存储，λ 难调 |
| 正交子空间（OGD 等） | 需算梯度投影，实现复杂 |
| 模块化（PackNet / PNN / HAT） | 线性增容，是**用容量买隔离**而非解决问题 |

**而本架构在原理上「应该」天然是局部的**：改 `c_A` 只影响 `W_A`，干扰理应为 0。
但实测不是。可能的原因（按本质性排序）：

| # | 原因 | 性质 |
|---|---|---|
| 1 | **码空间有几何**：移动 A 的码 = 同时改变它和**所有**邻居的关系 | **本质** |
| 2 | 共享基 `B_j` 是按「旧码分布」学的，A 的码一动，它在 `W_A` 中的角色就变了 | 需重训基 |
| 3 | STE 梯度会回传到共享基 → 一处改动牵动全局参数 | 梯度隔离问题 |

### 16.5 由此可以提出的可验证命题

作者直觉中那个「极其优雅的方式」，可以形式化为：

> **命题（局部性）**：能否学出一组共享基矩阵 `{B_j}`，使得「编辑任意一个码」
> 对其它 token 输出的影响**有可界定的上界**？

**这个重述的价值在于它可度量**：
- 编辑一个码，测量其它所有 token 输出的扰动
- 定义「局部性指标」= 扰动上界 / 编辑幅度
- 把它作为训练目标的一部分（正则项）

**它同时把「稳定性 vs 可塑性」从损失函数语言翻译成了参数化的局部性语言** ——
这个翻译本身就是贡献，因为它把一个难以度量的性质变成了可优化的量。

### 16.6 一个候选实现方向（尚未验证，仅记录）

要让「改一个 token 就改变它和其他 token 的链接」成立，需要**和交互对象相关**的项。
候选：给每个 token 追加一个低秩交互向量 `u_t ∈ R^r`（独立于码）：

$$x_i^{\text{out}} = \sum_j \alpha_{ij}\,(W_{t_i}x_i),\qquad
\alpha_{ij} = 1 + \langle u_{t_i}, u_{t_j}\rangle$$

满足的性质：
- 改 `u_A` **只影响 A 参与的交互**，不牵动全局
- 两个 token 的「链接强度」成为**显式可编辑量**
- 新 token 只需**追加一行 `u`**，无需重建模型 → 正好对应作者的意图 ②
- 参数量 `V × r`，r=32 时与码表同量级

> **⚠️ 必须先验证再实现**：该改动偏离标准注意力，训练稳定性未知。
> 参考教训：`code_param`（只改码位）看起来同样优雅，实测失败。
> **在「码表 vs LoRA」对比实验证明 per-domain 适配可行之前，不应叠加此项。**

# 检讨：语料改造的失败

**日期**：2026-02-14
**结论**：我（AI 助手）主导的语料配比改造**失败了**，把基座模型改坏了。
本文记录错误的事实、推理漏洞与教训，供后续对照。

---

## 一、我做了什么

把预训练语料从旧配置换成"修正配比"的新配置，理由是旧语料指令数据占比过高
导致格式过拟合。

| | 旧 `corpus_all` | 新 `corpus_mixed` |
|---|---|---|
| wiki | 0.47 GB | 0.47 GB (9.7%) |
| **skypile（网页抓取）** | **0 GB** | **3.46 GB (65.3%)** |
| instruct | 剩余全部（约 3.7 GB，~89%） | 1.17 GB (25.0%) |
| train tokens | 817 M | 1,193 M |

然后从零训练了一个 30000 步的 `base` 模型，耗时 4.1 小时。

---

## 二、实际结果：模型**变差了**，不是变好

用**确定性**的下一 token 预测（非采样）在 12 个探针上对比两个基座：

| 前缀 | 旧基座 top-1 | 新基座 top-1 | 旧概率 | 新概率 |
|---|---|---|---|---|
| 中国的首都是 | **北京** ✓ | 北京 ✓ | 0.700 | 0.494 |
| 中华人民共和国首都是 | 中华人民共和国 ✗ | “ ✗ | 0.093 | 0.031 |
| 北京是中国的 | 哪个 ✗ | “ ✗ | 0.276 | 0.054 |
| 水的化学式是 | **H** ✓ | ： ✗ | 0.356 | 0.160 |
| 一加一等于 | 一 ✗ | ， ✗ | 0.137 | 0.036 |
| 地球围绕 | **太阳** ✓ | 地球 ✗ | 0.554 | 0.393 |
| 《红楼梦》的作者是 | **曹雪芹** ✓ | 清代 ✗ | 0.400 | 0.207 |
| 太阳从 | **东方** ✓ | 西 ✗ | 0.194 | 0.035 |
| 法国的首都是 | 哪里 ✗ | **巴黎** ✓ | 0.360 | 0.078 |
| 请问 | **您** ✓ | ， ✗ | 0.046 | 0.080 |
| 答案是 | **：** ✓ | ， ✗ | 0.533 | 0.066 |
| 因为 | 没有 ✗ | 没有 ✗ | 0.018 | 0.012 |

**命中期望词：旧 7/12，新 2/12。**

更严重的是**置信度整体崩塌**：几乎每个探针的概率都大幅下降
（`答案是` 从 0.533 掉到 0.066，降了 8 倍；`太阳从` 从 0.194 掉到 0.035）。

**模型不再"确信"任何事** —— 它在低置信度下乱猜，这正是生成内容
"看着像话但内容空洞"的直接原因。

用户在使用网页对话界面后反馈"这个模型一直说胡话"，**用户的判断是对的**。

## 三、我的推理错在哪（四处）

### 错误 1：用困惑度（ppl）当唯一指标，并在不同语料间换算

我做了交叉评测（两个模型 × 两套验证集），得到：

```
旧模型：旧val 33.0   新val 114.9
新模型：旧val 48.7   新val  81.0
```

然后我**用一个单一系数把新模型的 ppl 换算回旧口径**：

```
"新基座 62.8 / 3.48 ≈ 18.0，比旧基座的 20.3 好"
```

**这个换算有两处硬伤：**

1. **ppl 在不同数据分布之间不可换算。** "语料难度"不是单一乘性因子 ——
   wiki、网页抓取、指令数据三者的难度结构完全不同，一个系数乘不过去。
2. **ppl 低 ≠ 知识多。** 一个模型完全可以在"可预测的废话"上拿到低 ppl。
   新语料里 65% 是网页文本，其行文套路性可能反而更强。

**正确做法：不要用 ppl 跨语料比较模型。** 要么用同一套保留测试集，
要么用**确定性的事实探针**（本次用的方法）。

### 错误 2：用"看起来合理"的解释掩盖了反证

我手上其实有过多个警告信号，但我用**同一个叙事**把它们全部解释掉了：

| 观察到的现象 | 我的解释 | 现在看 |
|---|---|---|
| 早期样本严重退化（"通海通海通海"） | "还没学到长文本规律" | 部分对，但我用它解释了**所有**异常 |
| 问答能力大幅下降 | "指令数据减少的直接后果，可以接受" | ✅ 这个解释对 —— 但我**没有追问它有多严重** |
| 重复变得明显 | "语料变难" | 其实是**置信度崩塌**的表现 |
| 交叉评测：旧模型在新 val 上 ppl 114.9 | "说明新语料更难" | 同样也可以解释为**"新语料更乱"** —— 我只检查了一个方向 |

**关键失误：我给每一个异常都找了一个"可以接受"的解释，却从未做过一次
能证伪自己结论的实验。**

### 错误 3：在不该做大改动的地方做了大改动

旧语料的问题诊断是**"格式过拟合"**。但我从未量化过这个问题：

- 到底有多少比例的样本包含空表格/重复列表模板？**没测。**
- 这个比例是否值得把整个语料结构推倒重来？**没评估。**

**我直接引入了一个占 65% 的新来源（网页抓取数据），其质量从未被评估过。**
这是把"可能有小问题"换成了"未经检验的大变量"。

**正确做法**：先测量模板样本占比，然后**过滤或降权那些样本**，
而不是替换整个语料构成。

### 错误 4：对指令数据的作用判断片面

我当时的判断："指令数据是给 SFT 用的，预训练里占比过高会导致格式过拟合。"

**这个判断只看到了它的坏处，没看到它的好处：**

- 指令数据是**人工撰写**的，语言干净、知识密集、逻辑完整
- 它占比高时，模型学到的是**有结构、有内容的中文**
- 我把它降到 25%，等于移除了语料中质量最高的那部分

而且"格式过拟合"的真实来源可能只是**一小部分模板化样本**，
不是指令数据整体。**我把"部分样本的问题"归因给了"整个来源"。**

## 四、本可以避免这个结果的检查

按代价从低到高排列，**任何一项做了都不会走到这一步**：

| # | 检查 | 代价 | 能发现什么 |
|---|---|---|---|
| 1 | **在训练前先跑事实探针基线** | 1 分钟 | 事实探针是确定性指标，训练后一跑就知道好坏 |
| 2 | 训练中途（如 step 10000）跑一次探针 | 1 分钟 | 早 3 小时发现问题，省下大部分时间 |
| 3 | 抽样人工检查 skypile 的文本质量 | 10 分钟 | 网页抓取数据的噪音水平 |
| 4 | 小规模消融（训 8000 步对比 3 种配比） | 3 小时 | 配比方向是否正确 |
| 5 | 量化模板样本占比，用过滤替代重构 | 30 分钟 | 原诊断是否成立 |

**第 1 项只要 1 分钟。我没做。**

## 五、代价

```
损失时间：语料重建 1.5 小时 + 编码 1.3 小时 + 训练 4.1 小时 ≈ 7 小时
连带影响：基于新基座的所有机制对比实验，前提都不成立了
用户信任：用户按我的建议使用模型，得到的是"一直说胡话"的体验
```

## 六、纠正措施

### 立即可做

1. **回退到旧基座**作为可用的对话/机制实验基座（它有真实的知识，7/12）。
2. **把事实探针固化进流程**：任何基座训练完成后，**先跑
   `scripts/33_diagnose_facts.py`**，再谈其他指标。它是确定性的、1 分钟的、
   无法被叙事掩盖的。

### 语料重建方向

去掉 skypile，只用两个**已验证质量**的来源：

```
wiki       0.47 GB   （高质量百科）
instruct   4.04 GB   （人工撰写）
skypile    0        （网页抓取 —— 本次证明它会稀释知识）
```

总量约 4.5 GB，与旧语料（4.2 GB）相当，但**指令占比从 89% 降到 ~90%？**

> ⚠️ 注意：去掉 skypile 后，instruct 自然占 ~90%，**又回到了旧语料的配比**。
> 这说明旧配比**可能本来就是这套数据下唯一合理的选择** ——
> 因为它只有两个高质量来源，而 wiki 只有 0.47 GB。

**所以在拿到更好的通用语料之前，语料配比这个问题可能无解。**
正确的应对是：**接受旧配比**，改用**过滤模板样本**的方式缓解格式过拟合。

### 流程上的改变

1. **不再用 ppl 跨语料比较模型。** 只用同一套保留集，或确定性探针。
2. **任何"改配置"的决策，先做小规模消融**，不直接全量重训。
3. **每个异常都要有一个能证伪它的实验**，而不是一个听起来合理的解释。
4. **用户的主观反馈（"它说胡话"）优先于我构造的指标。** 本次是用户先发现的。

---

## 七、一句话总结

**我把一个"有小毛病但知识扎实"的模型，换成了一个"看起来指标更好、
实际上什么都不知道"的模型 —— 而且我用事后编造的解释掩盖了所有反证，
直到用户用了一分钟发现它在说胡话。**

**根本教训：指标是用来证伪自己的，不是用来支持自己的。**
